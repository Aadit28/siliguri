# साथी

सिलीगुड़ी, पश्चिम बंगाल के बुज़ुर्गों के लिए बनाया गया स्थानीय सेवाओं और
पारिवारिक देखभाल का ऐप। ख़ास बात यह है कि उनके बच्चे, जो अक्सर दूसरे शहर या
दूसरे देश में रहते हैं, वहीं से माता-पिता की मदद कर सकते हैं।

एक ही कोडबेस iOS, Android और वेब पर चलता है (Expo, React Native, Expo Router),
और पीछे Supabase तथा कुछ serverless API routes हैं।

हिंदी डिफ़ॉल्ट भाषा है, अंग्रेज़ी एक टैप दूर। हर चीज़ का आकार और शब्द ऐसे चुने गए
हैं कि चश्मा उतारकर भी पढ़ा जा सके।

> यह अंग्रेज़ी [README.md](./README.md) का हिंदी रूप है। दोनों साथ-साथ अपडेट रखें।

## तीन पोर्टल

ऐप एक ही है, पर तीन तरह के लोगों के लिए। आप किसके रूप में साइन इन करते हैं, उसी
से तय होता है कि आपको क्या दिखेगा।

**पैरेंट (बुज़ुर्ग)।** सिलीगुड़ी में रहने वाले बुज़ुर्ग। सत्यापित स्थानीय सेवाओं
की डायरेक्टरी (डॉक्टर, अस्पताल, दवा की दुकानें, घर की मरम्मत, आवागमन, सरकारी
दफ़्तर), एक सहायक जो "कल डॉक्टर से मिलना है" को असली प्रदाता और कॉल की तैयारी में
बदल देता है — और "मुझे रोज़ रात 8 बजे BP की दवा याद दिलाना" को, हिंदी या
अंग्रेज़ी में, एक ऐसे reminder कार्ड में जो एक टैप की पुष्टि पर सेव होकर समय पर
बजता है। web build पर सहायक सुनता और बोलता भी है: mic का बटन hi-IN या en-IN में
बोली समझता है, और बोले हुए सवाल का जवाब बोलकर मिलता है। साथ में समुदाय बोर्ड,
याद-दिलावे, और एक टैप में कॉल करने वाला हेल्प डेस्क।

**गार्जियन (बच्चा)।** बुज़ुर्ग की अनुमति से उनके खाते से जुड़ता है, फिर उनके लिए
याद-दिलावे लगाता है, भरोसेमंद नंबरों की केयर टीम रखता है, सेवाएँ सहेजता है, और
दिनभर की हलचल का शांत सारांश देखता है — जिसमें "साथी से पूछें" का डिब्बा भी है,
जो "माँ का हफ्ता कैसा चल रहा है" का जवाब उनके असली याद-दिलावों और गतिविधि से
देता है। dev build पर पैरेंट के reminder पूरा करते ही फोन बजता है, और रोज़ रात
8 बजे (IST) दिन का सार पहुँचता है। समय हमेशा IST में दिखता है, चाहे गार्जियन
दुनिया में कहीं भी बैठा हो।

**एडमिन।** शहर की संचालन टीम। सेवाओं की डायरेक्टरी सँभालती है, सूचनाएँ प्रकाशित
करती है, कॉलबैक कतार निपटाती है, और शहर के सहायकों का प्रबंधन करती है। सब कुछ एक
शहर तक सीमित रहता है, इसलिए एक शहर का स्टाफ़ दूसरे शहर के नागरिकों का डेटा कभी
नहीं देखता।

## कहाँ क्या है

| हिस्सा | जगह |
| --- | --- |
| स्क्रीन | `app/`, Expo Router की फ़ाइल-आधारित routes |
| साझा कोड | `src/`: components, contexts, `lib/` |
| API | `server/`, 23 routes, एक ही dispatcher `api/index.js` के पीछे |
| लोकल API | `scripts/dev-api.js`, वही handlers पोर्ट 8788 पर |
| डेटाबेस | Supabase Postgres; schema और migrations repo की जड़ में |
| अनुवाद | `src/locales/en.json`, `src/locales/hi.json` |

## शुरुआत कैसे करें

Node 20.19.4 या नया चाहिए (Expo SDK 56)।

```bash
npm install
```

`.env.example` की नक़ल `.env` बनाकर Supabase की जानकारी भरें। फिर दो टर्मिनल में
API और ऐप चलाएँ:

```bash
node scripts/dev-api.js
```

```bash
npm run web
```

ऐप <http://localhost:8081> पर खुलेगा और पोर्ट 8788 पर API से बात करेगा।
`npm run android` और `npm run ios` इसी तरह Expo Go से चलते हैं। Windows पर
`./start.ps1` साथ में दिए गए पोर्टेबल Node से वेब ऐप चला देता है।

बैकएंड के बिना भी ऐप चलता है। सेवाओं की सूची ऐप में रखी सिलीगुड़ी की प्रति से आ
जाती है, और नीचे दिए डेमो खाते ऑफ़लाइन ही साइन इन कर लेते हैं।

## डेटाबेस तैयार करना

SQL फ़ाइलें इसी क्रम में चलाएँ। बाद वाली फ़ाइलें पहले वाली से बनी टेबलों पर
निर्भर हैं।

1. `supabase-schema.sql`
2. `supabase-auth-migration.sql`
3. `supabase-migration-2.sql`
4. `supabase-migration-3.sql` (शहर, सूचनाएँ)
5. `supabase-migration-4-phone-auth.sql`
6. `supabase-migration-5-city-helpers.sql`
7. `supabase-migration-6-phone-otp.sql`
8. `supabase-migration-7-family-guardian.sql`
9. `supabase-migration-8-otp-atomic.sql`
10. `supabase-migration-9-fixes.sql`
11. `supabase-home-service-migration.sql`
12. `supabase-pilot-readiness-migration.sql`
13. `supabase-migration-10-callback-city.sql` (कॉलबैक कतार को शहर तक सीमित करना)

फिर डेटा भरें:

```bash
node --env-file=.env scripts/seed.mjs
```

```bash
node --env-file=.env scripts/seed-demo-accounts.mjs
```

पहली स्क्रिप्ट 58 सिलीगुड़ी सेवाएँ डालती है। दूसरी एक डेमो परिवार और एक एडमिन
खाता बनाती है।

## कॉन्फ़िगरेशन

`.env` gitignore में है और deploy के लिए Vercel की सेटिंग्स में इसकी नक़ल रहती है।

| वेरिएबल | काम |
| --- | --- |
| `EXPO_PUBLIC_SUPABASE_URL` | Supabase प्रोजेक्ट का URL |
| `EXPO_PUBLIC_SUPABASE_ANON_KEY` | anon key, क्लाइंट में सुरक्षित, RLS से घिरी |
| `EXPO_PUBLIC_API_BASE_URL` | ऐप `/api/*` कहाँ ढूँढे |
| `SUPABASE_SERVICE_ROLE_KEY` | सिर्फ़ सर्वर पर। ऐप बंडल में कभी नहीं |
| `DEEPSEEK_API_KEY` | सहायक का planner। न हो तो लोकल planner सब सँभालता है |
| `DEEPSEEK_MODEL` | OpenCode Go key किस model को कॉल करे। अभी `kimi-k2.5` |
| `OPENAI_API_KEY` | फ़ोटो वाले सवालों के लिए, जिन्हें text model नहीं पढ़ पाते |
| `WHATSAPP_*` | OTP साइन-इन और गार्जियन लिंक के लिए ज़रूरी |
| `AI_USER_DAILY_MAX`, `AI_GLOBAL_DAILY_MAX` | सहायक की सीमाएँ, डिफ़ॉल्ट 120 और 1200 |
| `CRON_SECRET` | गार्जियन के रोज़ाना digest cron की पहचान (रात 8 बजे IST) |

## जो जान-बूझकर नहीं बनाया

कुछ चीज़ें सोच-समझकर छोड़ी गई हैं, और यह जानना ज़रूरी है कि कौन-सी।

ऐप पैसा नहीं भेजता। भुगतान UPI deep link से होता है, यानी ऐप उपयोगकर्ता का अपना
UPI ऐप खोल देता है और पैसे को कभी छूता नहीं।

ऐप दवा नहीं बेचता। आगे की योजना में पर्चा किसी लाइसेंस वाली फ़ार्मेसी को जाएगा,
जिसके पास लाइसेंस और Schedule H की जाँच दोनों होंगे। साथी फ़ार्मेसी नहीं है।

सहायक चिकित्सा सलाह नहीं देता। उसकी चेतावनी तय और जाँची हुई है, हर जवाब में एक
जैसी, और कभी भी मॉडल की लिखी हुई नहीं।

बुज़ुर्ग का डेटा सिर्फ़ सहमति से साझा होता है। गार्जियन की पहुँच दर्ज रहती है और
वापस ली जा सकती है। असली शुरुआत से पहले बुज़ुर्ग को खुद ऐप में सहमति देनी चाहिए,
न कि बच्चे को कोड पढ़कर सुनाना चाहिए।

## असली पायलट से पहले

- WhatsApp Business की जानकारी। इसके बिना OTP साइन-इन और गार्जियन लिंक दोनों 503
  लौटाते हैं, और यूज़रनेम-पासवर्ड ही अकेला रास्ता बचता है।
- बुज़ुर्ग की तरफ़ से सहमति की पुष्टि, DPDP Act 2023 को देखते हुए।
- दर-सीमाएँ मेमोरी से डेटाबेस में जाएँ। अभी हर बार serverless instance बदलने पर
  रीसेट हो जाती हैं।
- `favorites` की row-level security अब भी Supabase Auth सत्र माँगती है, जो यह ऐप
  बनाता ही नहीं। वे लिखाई API से होकर जानी चाहिए।

## सुरक्षा

service role key सिर्फ़ सर्वर पर रहती है और ऐप बंडल में कभी नहीं जाती। क्लाइंट को
सिर्फ़ anon key दिखती है, और उसके पीछे row-level security खड़ी है। परिवार, auth
और OTP की टेबलें केवल service role से पहुँच में हैं। हर एडमिन route सर्वर पर
भूमिका जाँचता है, इसलिए क्लाइंट का गेट सुविधा है, सुरक्षा नहीं।
