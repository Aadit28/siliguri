# साथी पर काम करना

> यह अंग्रेज़ी [contributing.md](./contributing.md) का हिंदी रूप है। दोनों साथ-साथ अपडेट रखें।

यह उसके लिए लिखा गया है जो आगे इस काम को सँभालेगा। मान लिया गया है कि ऐप आपके यहाँ
चल रहा है (README देखें), और इसमें वे आदतें हैं जो इस ख़ास codebase को इस तरह
टूटने से बचाती हैं कि उसके उपयोगकर्ता शिकायत तक न कर सकें।

## आप किसके लिए लिख रहे हैं

इस ऐप को इस्तेमाल करने वाला बुज़ुर्ग करीब सत्तर साल का है, अंग्रेज़ी से ज़्यादा
आराम से हिंदी पढ़ता है, और फ़ोन को हाथ भर दूर रखकर देखता है। वह कोई error संदेश
दोबारा नहीं पढ़ेगा, उसे पता नहीं चलेगा कि permission वाला सवाल किस लिए आया था, और
अगर कोई बटन कुछ नहीं करता तो वह यही मानेगा कि गलती उसी से हुई।

उनका बच्चा तीन timezone दूर है और स्क्रीन नहीं देख सकता। जब कुछ काम नहीं करता, वह
चलकर आकर देख भी नहीं सकता।

नीचे के कई नियम इसी से बने हैं। ये पसंद-नापसंद की बात नहीं हैं।

## चुपचाप फ़ेल होना मना है

इस codebase में निगली गई एक error का मतलब ब्लड-प्रेशर की दवा की एक खुराक छूट जाना
हो सकता है। अगर कुछ नहीं चला, तो इंसान को बताना ही होगा, उसकी अपनी भाषा में, ऐसे
शब्दों में जो कहें कि अब करना क्या है।

साफ़-साफ़:

- जो `catch` कोई default लौटाता है, उस पर एक टिप्पणी चाहिए कि वहाँ चुप रह जाना
  सही क्यों है। अगर आप वह टिप्पणी नहीं लिख सकते, तो error सामने लाइए।
- अगर कोई write नाकाम हो जाए, तो optimistic UI को सफलता दिखाते हुए मत छोड़िए। उसे
  वापस पलट दीजिए।
- अगर reminder सेव हो गया पर उसका alert तय नहीं हो सका, तो यह बताइए। `addEvent`
  ठीक इसीलिए `alertProblem` लौटाता है।
- कोई fetch खाली लौटी, इस वजह से लोकल डेटा मत मिटाइए। नाकाम request से आई खाली
  सूची और सचमुच की खाली सूची, दोनों एक जैसी दिखती हैं। `mergeReminders` इसी वजह
  से `complete` flag लेता है।

## दोनों भाषाएँ, हमेशा

हिंदी डिफ़ॉल्ट है, बाद में किया गया अनुवाद नहीं। जब आप उपयोगकर्ता को दिखने वाला
कोई text जोड़ें:

key को `src/locales/en.json` और `src/locales/hi.json`, दोनों में डालें। दोनों
बराबरी पर हैं और बराबरी पर ही रहने चाहिए। कोड में लिखा `defaultValue` किसी
बिना-merge हुई branch का सहारा भर है, हिंदी string का विकल्प नहीं।

हिंदी ऐसी लिखिए जो बुज़ुर्ग पढ़ सके। सीधे शब्द, और जहाँ आम हिंदी शब्द मौजूद है
वहाँ अंग्रेज़ी को देवनागरी में मत लिखिए। जो शब्द `hi.json` में पहले से हैं उन्हीं
को दोबारा इस्तेमाल कीजिए, ताकि पूरा ऐप एक ही आवाज़ में बोले।

यह याद रखिए कि सर्वर से आने वाली error की लाइनें अंग्रेज़ी में हैं। उन्हें कच्चा
दिखाने के बजाय `localizedServerError` से होकर भेजिए।

## आकार और कंट्रास्ट शर्तें हैं

`src/lib/theme.ts` में `TAP` 56 है, और यह सबसे नीचे की सीमा है, सुझाव नहीं। अगर
किसी control को छोटा दिखना ही है, तो भी छूने का इलाका 56 ही रखिए। React Native
Web hit testing के लिए `hitSlop` को नज़रअंदाज़ कर देता है, इसलिए वेब बिल्ड में
डिब्बे में padding डाल देना काफ़ी नहीं है।

आम text `font.sm` (16) या उससे बड़ा होता है। `font.xs` कैप्शन के लिए है।

रंगों की जोड़ी को WCAG AA पास करना चाहिए। अंदाज़े से देखने के बजाय ratio निकालिए।

## समय यानी Indian Standard Time

पैरेंट सिलीगुड़ी में है। गार्जियन कहीं भी हो सकता है। उपयोगकर्ता को दिखने वाली हर
तारीख़ IST में है। आज की तारीख़ चाहिए तो `new Date()` की जगह
`src/lib/notifications.ts` का `todayISO()` इस्तेमाल कीजिए, वरना New Jersey में
बैठा गार्जियन गलत दिन का reminder लगा देगा।

## डेमो रास्ता ज़िंदा रखें

`src/lib/family.ts` का हर वह function जो नेटवर्क पर जाता है, उसमें demo tokens के
लिए एक branch चाहिए। एक भी छूटा तो demo ठीक उसी के सामने टूटेगा जिसे आप दिखा रहे
थे, और उसे एक 401 दिखेगा जिसका मतलब वह समझ ही नहीं सकता। fixtures
`src/lib/demoFamily.ts` में रखे हैं।

## असली जाँच सर्वर पर होती है

`/admin` पर क्लाइंट का गेट सुविधा है। हर admin route सर्वर पर कॉल करने वाले की
भूमिका दोबारा जाँचता है, और हर family route उस link को दोबारा जाँचता है। इसे ऐसा
ही रहने दीजिए, और जब आप नागरिकों का डेटा रखने वाली कोई टेबल जोड़ें, उसमें
`city_id` डालिए और query को सर्वर पर ही सीमित कीजिए।

दो ख़ास जाल:

`x-forwarded-for[0]` पर किसी भी काम के लिए भरोसा मत कीजिए। उसे क्लाइंट सेट करता
है। `requestIp()` इस्तेमाल कीजिए।

model के जवाब को नीति मत बनने दीजिए। सहायक की चेतावनी तय और जाँची हुई copy है, और
उसके सुझाए काम उन्हीं service ids के आगे छाने जाते हैं जो क्लाइंट ने सचमुच भेजी
थीं। दोनों भार उठा रहे हैं।

## Pull request खोलने से पहले

अभी कोई test suite नहीं है, इसलिए हाथ से की जाने वाली जाँच और भी ज़रूरी हो जाती
है:

```bash
npx tsc --noEmit -p tsconfig.json
```

फिर जो आपने छुआ है उसे browser में उसी खाते से चलाकर देखिए जो असल में उस तक
पहुँचेगा। गार्जियन का flow बदला है तो `demo.guardian` से साइन इन करके एक reminder
लगाइए। API छुआ है तो उसे curl कीजिए और मान लेने के बजाय status code पढ़िए।

pull request के विवरण में वही दावे लिखिए जो आपने खुद होते हुए देखे हों। "काम करना
चाहिए" कोई जाँच नहीं है।

## Commit संदेश

गद्य में लिखिए कि व्यवहार क्या बदला और वह क्यों मायने रखता था, बुलेट पॉइंट की
कतरनों में नहीं। एक साल बाद log पढ़ने वाले को यह समझ आना चाहिए कि टूटा क्या था,
सिर्फ़ यह नहीं कि कौन-सा function कहाँ चला गया।
